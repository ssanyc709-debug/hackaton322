# QA-отчёт: «ИИ-помощник покупателя мебели»

Проверяемый продукт: `app/` в состоянии `HEAD f5030e8` («Готовая версия приложения
(бэкенд) 1»). В ходе проверки код приложения **не менялся**: найденные дефекты
описаны в [`docs/QA-ERRORS.md`](QA-ERRORS.md) и закреплены тестами. Дефекты №1
и №2 после проверки исправлены; в таблицах ниже сохранены исходные наблюдения
с пометкой «было», рядом — фактическое поведение после исправления.

Источник истины: `_upstream/CONTRACT.md` (v1.1), `_upstream/schemas/*.json`,
`_upstream/examples/*`, `data/*.json`.

## Как запускать

```bash
# весь набор (включая исходные тесты репозитория)
python3 -m unittest discover -s tests -t .

# только QA-набор, одной командой
python3 -m unittest \
    tests.test_qa_entrypoint tests.test_qa_input tests.test_qa_response \
    tests.test_qa_bounds tests.test_qa_history tests.test_qa_statuses \
    tests.test_qa_catalog tests.test_qa_injection tests.test_qa_determinism

# метрика точности извлечения (228 размеченных реплик, 0 токенов модели)
python3 bench/accuracy.py
python3 bench/accuracy.py --check      # упасть, если точность хуже замороженной

# по блокам
python3 -m unittest tests.test_qa_bounds        # границы характеристик
python3 -m unittest tests.test_qa_statuses      # clarify / no_match
python3 -m unittest tests.test_qa_catalog       # проверочный каталог
python3 -m unittest tests.test_qa_injection     # защита от манипуляций
python3 -m unittest tests.test_qa_determinism   # повторяемость
```

Все тесты работают через боевой путь `python -m app.main --catalog …`:
отдельный процесс, `stdin` в UTF-8, `ASSISTANT_OFFLINE=1` (без сети и без модели),
свой `ASSISTANT_CACHE_DIR` в `tempfile` (в `data/cache` ничего не пишется).
Скрипт `./run` не исполняется — проверяется статически (существует, непустой,
содержит `app.main`, `--catalog`, `$@`), как и решено по итогам обсуждения.

## Что осознанно не проверяется

| Решение | Причина |
|---|---|
| `./run` не исполняется | по договорённости; проверяется статически, поведение — через `python -m app.main` |
| конкретные коды ошибок (2, 3, 1) | контракт фиксирует только ненулевой код; тесты требуют «ненулевой + пустой stdout» |
| побайтовое совпадение с `_upstream/examples/*` | §4: точное совпадение ID и текста не требуется; допустимость варианта проверяется по каталогу |
| тексты вопросов и объяснений | §5: формулировки свободные; проверяется смысл (поля, суммы, города, категории) |
| обращения к модели | режим офлайн; доля запросов без модели измеряется стендом (`bench/load.py`), живой путь — отдельным smoke-тестом |

## Ограничения проверки

* Модель не вызывается (`ASSISTANT_OFFLINE=1`): проверяется детерминированный
  лексический путь и все правила подбора. Качество разбора «свободных»
  формулировок моделью этим набором не измеряется — для этого есть
  `bench/load.py` и отдельный живой smoke-тест (см. ниже).
* Живой шлюз проверен отдельно (21.11.2026, ключ команды): три реплики, которые
  лексикон закрыть не может («деревяшка с четырьмя ножками», «сиденье со
  спинкой», «предмет, за которым пишут»), дали `ok` с правильной категорией;
  234–240 токенов и 2,2–3,7 с на вызов, без `429`/`403`. Подробности —
  `docs/TOKEN_BUDGET.md`, раздел «Измеренный обмен одного вызова».
* Проверочный каталог организаторов недоступен, поэтому устойчивость
  к нему проверена на синтетических каталогах: 250 объявлений, другие ID и
  цены, экстремальные значения, отсутствующие категории и характеристики.
* Все проверки — чёрный ящик: тесты не импортируют внутренние модули решения
  (кроме чтения константы `SYSTEM_PROMPT` в блоке 8 и `schema_errors` из
  собственной обвязки), не подменяют функции и не зависят от порядка запуска.
